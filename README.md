# 关系图谱 · RelationGraph

用一句话记录设备关系，用图谱回答问题。

打开是一个全屏的关系图（深色、可缩放拖动），底部一个输入框。你说「33#湿矿设备箱电源来自电除尘」，它把这句话变成一个节点和一条边；三个月后你问「33#湿矿电源哪来的」，它照着数据库回答，并且告诉你这条信息是哪天记的。

**核心设计：模型只做翻译，数据库负责回答。**

模型不参与"记住"和"回答"，只负责把中文转成结构化的三元组。答案永远由数据库里的事实拼装而成。所以它不会编造一条你没记过的线路——没有记录就明确说"当前记录里没有"。

## 一、装到手机上

APK 位置：`build/app/outputs/flutter-apk/app-release.apk`

1. 把 APK 传到安卓手机（微信/数据线/网盘都行）
2. 手机上点开安装，遇到"未知来源"提示选择"仍要安装"
3. 打开后如果图是空的，先点右上角 **⚙ 设置** 填模型配置（见下一节）

> 这个 APK 用的是调试签名，自己用、给同事用都没问题；要上应用商店才需要自己的 keystore。

## 二、配模型（任何 OpenAI 兼容接口）

点右上角 **⚙** 进入设置，三个模型各一个入口，点进去单独配：

| 入口 | 用途 | 是否必填 |
|---|---|---|
| 大语言模型 (LLM) | 理解你说的话、抽出关系、判断是记录还是提问 | **必填**，不填 App 用不了 |
| 语音合成 (TTS) | 每次回答自动念出来；面板右上角喇叭可静音/重播 | 选填 |
| 语音识别 (ASR) | 输入框右边的麦克风，说一句话直接识别成文字 | 选填 |

LLM 的服务商预设（点一下自动填地址和模型名）：

| 服务 | Base URL | 模型名 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 本机 Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` |

**温度保持 0～0.2**。抽关系不需要创造力，高了模型爱自由发挥。

三个模型的 Key 都存在手机系统加密存储（Android Keystore / iOS Keychain）里，不写日志、不进备份。

## 三、怎么用

**记一条**（会先弹确认卡片，点了"记住这个关系"才入库）

```
主机房交换机1#口网线到弱电井交换机2#口
```
```
弱电井交换机电源来自东北角配电箱
```
**提问**（自动定位到图上并高亮那条边）

```
弱电井电源哪来的
弱电井交换机2#口连接哪里
```

**改接 / 纠错**（重点是"旧的会自动失效"，不是多画一条线）

```
弱电井交换机电源改到二楼配电箱了
刚才记错了，弱电井交换机电源实际在三楼配电箱
```

确认卡片上会先告诉你「将替换旧记录：电源来自「三楼配电箱」」，点了确认之后：

- 旧的那条被标为**已失效**，图谱上不再显示
- 新的一条生效，图上是 3弱电井交换机 → 三楼配电箱
- 旧的没有删，进设备详情还能看到一条划掉的「已失效」记录，可追溯

**主动作废**（不想加新的，只是这条不成立了）

```
弱电井交换机电源不在来自二楼
这条电源记录作废
```

会先列出将要作废的记录，二次确认后才动手。

**没说全时**（直接追问，不会瞎猜）

```
弱电井交换机的电源线编号是多少
→ 当前记录里没有「弱电井交换机电源线编号」的相关依据。
```

## 四、数据存在哪

全部在这台手机的本地 SQLite 里（`relation_graph.db`），不上传任何服务器。联网只用于调用你自己配置的模型接口。

卸载 App 会连数据一起删掉。目前版本还没做导出备份——**重要数据请先在别的笔记里留一份底**（导出功能在 V2）。

## 五、自己编译

需要 Flutter SDK ≥ 3.24 和 Android SDK 34。

```bash
flutter pub get
flutter build apk --release          # 产物在 build/app/outputs/flutter-apk/
flutter build apk --debug            # 想快速试跑用这个
flutter run                          # 插着手机直接运行
```

iOS（需要 Mac + Xcode）：

```bash
flutter build ios --release
# 再用 Xcode 打开 ios/Runner.xcworkspace 配置证书，Archive 出 IPA
```

> `android/gradle/wrapper/gradle-wrapper.properties` 里的 Gradle 分发地址已经换成腾讯云镜像，国内编译不会卡在下载上。如果镜像失效，改回 `https://services.gradle.org/distributions/gradle-9.3.1-bin.zip` 即可。

```
    ├── settings_screen.dart  模型配置

```

### 几个关键取舍

- **图谱用 WebView + Cytoscape.js**，而不是自绘。路径高亮、节点拖动、增量更新都是现成的，深色主题也好做。
- **不做全图重排**。新增节点只做局部松弛（`relax()`），已有节点位置不动，避免"每记一条全图洗牌"。
- **谓词白名单**（`Predicate` 枚举）。模型只能从 10 个关系里选，不允许自造。同一个意思永远存同一个 code，否则「电源来自」「供电」「接电」会变成三条不同的边。
- **确认卡片是强制的**，不是首次才弹。脏数据进图谱后的清理成本，比每次多点一下高得多。

## 七、语音

语音有三条路，设置页里各选各的，互不影响：

| 方式 | 联网 | 成本 | 适合 |
|---|---|---|---|
| 手机内置（系统 TTS / SpeechRecognizer） | 不需要 | 免费 | 现场没信号、不想填 Key |
| 离线模型（自带 sherpa-onnx） | 不需要 | 免费，占 25MB | 手机没有系统识别服务时 |
| 在线接口 | 需要 | 按量 | 追求识别质量 |

**识别方式三选一**（设置 → 语音识别，顶部三个按钮）：

- **手机内置**：调 `SpeechRecognizer`，不填 Key，但要有系统识别服务。部分国产 ROM 没开放。
  页面上有「检测本机识别能力」，会列出系统里注册了识别服务的应用。
- **离线模型**：App 自己带引擎（APK 里约 15MB 原生库），模型首次点下载（71MB 压缩包，解压后占 25MB）。
  下完就不需要网络，也不需要系统支持。适合手机没有识别服务的情况。
- **在线接口**：走 OpenAI 兼容格式，识别质量最好。

**热词偏置**：选「离线模型」时，App 会自动把库里已有的设备名做成热词喂给识别引擎，
让它倾向于往这些词上靠。只取纯中文片段（「湿矿设备箱」「电除尘」），最多 80 个 ——
模型词表里没有阿拉伯数字和 `#`，带编号的整串写进去编码不了。新增设备后第一次说话会自动重建。

配合一条归一化规则：**中文数字 ↔ 阿拉伯数字互通**。「七号炉九米设备箱」和 `7#炉9米设备箱`
现在算同一个名字，「信号线」里的「号」不受影响。这条对在线识别同样生效。

离线模型装在哪：应用私有目录 `asr_models/`，卸载 App 时一起清掉。下载源是 GitHub，
内置了 ghfast.top / gh-proxy.com / ghproxy.net 三个加速镜像，直连超时会自动换。

语音合成（TTS）仍然是二选一：手机内置 / 在线接口，开关在语音合成页顶部。

在线部分分两大派，在设置页选「接口协议」即可：

| 协议 | 端点 | 谁在用 |
|---|---|---|
| OpenAI 标准 | `POST /v1/audio/speech`、`POST /v1/audio/transcriptions`（multipart 上传） | OpenAI、硅基流动等 |
| Chat 格式 | `POST /v1/chat/completions`，音频放在 `audio` / `input_audio` 字段 | 小米 MiMo、通义等 |

选「自动」时按地址和模型名判断（带 `mimo`、走 `xiaomimimo.com` / `dashscope` 的按 Chat 格式）。

**小米 MiMo 怎么配**：语音合成页点「小米 MiMo」，自动填好
`https://api.xiaomimimo.com/v1` + `mimo-v2.5-tts` + Chat 格式 + 音色「冰糖」；
语音识别页同理填 `mimo-v2.5-asr`。只需再贴 API Key，然后点「试听一句 / 试说一句」验证。

- **说一句就记**：点输入框右边的麦克风 → 说话 → 再点一次停止。识别结果自动发送，走的还是确认卡片流程。
- **回答自动播报**：面板右上角喇叭，正在念时点一下 = 停止并静音，静音状态再点 = 解除并重播。
- **一键获取音色**：OpenAI 标准协议会试探服务端的音色接口；Chat 格式（MiMo）直接用官方预置音色列表（`冰糖 / 茉莉 / 苏打 / 白桦 / Mia / Chloe / Milo / Dean`）。

录音用 16kHz 单声道 **WAV**（MiMo 只收 wav/mp3，OpenAI 也认 wav），一句话几十到几百 KB。上传完立即从临时目录删除。

**用手机内置识别**：设置 → 语音识别 → 打开「使用手机内置识别」。
它调的是 Android 的 `SpeechRecognizer`（iOS 上是 `SFSpeechRecognizer`），用的是手机里已经装好的语音服务，
**不经过本 App 的服务器、不用填 Key**。语言填 `zh-CN`。下面还有一个「仅本机识别」开关：
打开后强制离线，录音不出手机；系统没装离线语音包时会直接失败并在页面上写明原因。

注意：这条路的识别质量完全取决于手机厂商预装的语音服务。小米、华为、OPPO 的国行 ROM 通常带中文识别，
部分精简 ROM 会裁掉，此时 App 会提示「这台手机没有可用的语音识别服务」，改回在线识别即可。

**点画面空白处可以收起回答/详情面板**；确认类面板（记住关系、作废记录）必须点按钮，防误触。

## 七点五、备份与恢复

设置 → 数据 → 备份与恢复。导出一个 `.json` 文件，通过系统分享面板存到微信 / 云盘 / 文件管理器。

**导出内容**：全部实体、全部关系（含已失效的历史）、节点坐标、模型配置。
选择「同时导出 API Key」时 Key 也会明文写进去，默认不带。

**导入**：选文件 → 显示备份时间和数据量 → 确认后**替换**当前全部数据。
是替换不是合并 —— 换手机、重装的场景里合并只会让同名实体掺在一起，更难理清。
所以导入前建议先导出一份。

恢复后模型配置会一起生效；如果备份里没带 Key，需要重新填。

## 八、已知限制

- 没有导出/备份（V2）
- 没有照片附件（V2）
- 单机版，不支持多设备同步
- 节点超过约 800 个时，全图模式会开始卡；应改用邻域视图（V2 提供切换）
- 关系类型目前固定 10 种，不能自定义（V3）
- 语音播报不能调语速/音调（走的是服务商默认）
